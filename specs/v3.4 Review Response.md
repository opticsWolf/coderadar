## 1. The Latency Gap — Accepted and Resolved

The reviewer's math is correct and conclusive:

| Operation | In-memory (v3.3) | Macrame API (v3.4 naive) | Differential |
|-----------|-----------------|--------------------------|-------------|
| Single reverse-index lookup | ~10 ns (`HashMap::get`) | ~20–100 µs (DB traversal) | **2,000–10,000×** |
| 50,000-function full scan (`caller_count == 0`) | ~0.5 ms | ~1,000 ms | **2,000×** |
| 3-hop agent traversal | N/A (not in v3.3) | 1.72 ms (Macrame) | Added capability |

Macrame is the wrong tool for the Pest Query Engine's inner loop. It IS the right tool for persistence, bitemporality, and agent-facing graph exploration.

### Resolution: Mandatory Hybrid Architecture

```
                    ┌──────────────────────────┐
                    │      Macrame (.db)        │
                    │  • Source of Truth        │
                    │  • All writes go here     │
                    │  • Bitemporal history     │
                    │  • DiskANN vectors        │
                    │  • Agent traversals       │
                    │  • Audit / integrity      │
                    └──────────┬───────────────┘
                               │
                    ┌──────────▼───────────────┐
                    │  In-Memory Projected Graph │
                    │  • Derived from Macrame   │
                    │  • Reverse indexes        │
                    │  • Pest query execution   │
                    │  • L1/L2 resolution cache │
                    │  • Rebuildable from ledger│
                    └──────────────────────────┘
```

**The in-memory projected graph is a rebuildable derivative** — exactly like Macrame's own `links_current` table. It is built from the ledger, can be verified against it, and can be rebuilt from scratch at any time. This follows Macrame's Doctrine VII ("Derivative state is disposable") applied to CodeRadar's domain.

### Updated Architecture (replaces amendment A1–A3)

```
Ingestion:
  1. Parse file → ExtractedUnits (tree-sitter, unchanged)
  2. Diff old vs new → Patch (unchanged)
  3. Write to Macrame:
     a. Retire old entities/edges (valid_to = now)
     b. Assert new entities/edges (valid_from = now)
  4. Update in-memory projected graph:
     a. Remove retired edges from reverse indexes
     b. Insert new edges into reverse indexes
     c. Recompute affected MROs
  5. Re-resolve affected symbols (unchanged)

Query:
  Structural (Pest): → In-memory projected graph (< 100ms)
  Agent exploration: → Macrame traversals (1.72ms 3-hop)
  Temporal (as_of):  → Macrame bitemporal queries
  Vector search:     → Macrame DiskANN (246µs top-10)
  Full-text:          → Macrame FTS5
```

### What stays in-memory

| Structure | Purpose | Build cost |
|-----------|---------|------------|
| `callers_by_callee: HashMap<Id, BTreeSet<Id>>` | `caller_count`, `find_callers()` | Rebuilt from Macrame edges on startup / integrity check |
| `callees_by_caller: HashMap<Id, BTreeSet<Id>>` | Call graph fan-out | Same |
| `importers: HashMap<ModuleId, BTreeSet<ModuleId>>` | Module dependency queries | Same |
| `subclasses: HashMap<ClassId, BTreeSet<ClassId>>` | MRO invalidation | Same |
| `overridden_by: HashMap<FunctionId, BTreeSet<FunctionId>>` | Method override queries | Same |
| `resolution_cache` (§5.4) | Resolution memoization | Always was in-memory |
| Entity metadata (name, kind, line, spans) | Pest filter evaluation | Loaded from Macrame at startup, updated incrementally |

These are NOT the v3.3 ArcSwap arenas. They are simple, single-writer `HashMap`s behind an `RwLock<Arc<ProjectedGraph>>`. Reads take a snapshot by cloning the `Arc` (one atomic increment). The writer builds a new `ProjectedGraph`, then swaps the `Arc` — same pattern as Macrame's `links_current` swap but vastly simpler than v3.3's per-arena `ArcSwap<SlotMap>`.

### Startup reconciliation

On `CodeGraph::open()`:
1. Macrame loads `links_current` → produces all current entity/edge assertions
2. Projected graph is built from these assertions (~10–50ms for typical repos)
3. Watcher begins; incremental updates keep projection in sync

On integrity violation (detected by periodic `verify_integrity()`):
1. Drop the projected graph
2. Rebuild from Macrame ledger
3. Log warning; agent continues uninterrupted (reads briefly fall back to Macrame traversals)

## 2. Partial Coverage Principle — Revised

The reviewer correctly identifies that calls to external libraries (`requests.post()`, `os.path.join()`) are a valid and expected case. The original wording was too strict.

### Revised principle (replaces A9)

> **6.1a Partial Coverage Principle**
>
> A partially-resolved flow through **internal** entities is worse than an unresolved one. When the resolution cascade resolves some internal edges in a call chain but leaves gaps to other internal entities, the agent receives an incomplete graph and falls back to reading files.
>
> **Rules:**
> 1. An edge to an **external** target (standard library, third-party package, builtin) is always emitted with `target_kind: "external"` and the target name. These are NOT dead ends — agents understand they terminate at external boundaries.
> 2. An edge to an **internal** target whose own edges are missing MUST NOT be emitted. This IS a dead end. Mark the source's resolution as `Unresolved { reason: IncompleteFlow }` instead.
> 3. The `::toplevel` sentinel (§6.6) is always internal. Module-level references without resolution targets follow rule 2.
>
> **Validation:** For each framework and language, test a canonical end-to-end internal flow. The graph must connect all internal hops, or report the specific boundary where resolution failed. External edges are counted as resolved (the boundary is known). Measured by agent A/B: 0 Read/Grep for the flow question.

## 3. SQLite Mirror — Withdrawn

The reviewer is correct: maintaining a SQLite mirror introduces synchronization burden with no benefit. The in-memory projected graph handles structural queries. The suggestion is withdrawn from the amendment.

### Updated A10

> **Drop Cypher templates (§7.3).** The six template queries are reimplemented as Macrame API calls for agent exploration. Structural Pest queries execute against the in-memory projected graph. No SQLite mirror is needed.

## 4. FFI Safety — Accepted

The reviewer's concern about ABI-versioned flat buffer unpacking is well-founded. Added to the amendment:

### Addition to A8 (after wire format specification)

> **8.1a Python-Side Decoder (mandatory)**
>
> The Python layer MUST use a typed decoder that validates the ABI version before unpacking:
>
> ```python
> @dataclass(frozen=True)
> class FlatBufferDecoder:
>     abi_version: int
>     _entity_row_size: int = 128
>     _edge_row_size: int = 56
>     _ref_row_size: int = 48
>
>     @classmethod
>     def from_meta(cls, meta: bytes) -> "FlatBufferDecoder":
>         abi = struct.unpack_from("<I", meta, 0)[0]
>         if abi != EXPECTED_ABI_VERSION:
>             raise ABIError(
>                 f"Kernel ABI {abi} != expected {EXPECTED_ABI_VERSION}. "
>                 f"Reinstall coderadar or rebuild the Rust extension."
>             )
>         return cls(abi_version=abi)
>
>     def decode_entity(self, arena: bytes, offset: int) -> Entity:
>         row = self._entity_row_size * offset
>         kind = struct.unpack_from("<B", self._buf, row)[0]
>         # ... field-by-field unpacking with arena string resolution
> ```
>
> The decoder is the **single source of truth** for the wire format. Any layout change bumps `EXPECTED_ABI_VERSION` in both `buffers.rs` and the Python decoder. Mismatch produces a clear error message — never a segfault.

## 5. Performance Budgets — Updated

The v3.4 amendment must acknowledge the hybrid architecture in the performance budgets.

### Updated §22.1 targets

| Metric | Target | Backend |
|--------|--------|---------|
| Structural query (streaming, simple `where`) | < 5 ms to first result | In-memory projected graph |
| Structural query (aggregated, full scan) | < 100 ms | In-memory projected graph |
| Agent traversal (3-hop explore) | < 5 ms | Macrame (measured: 1.72 ms) |
| Agent traversal (impact, depth 5) | < 20 ms | Macrame traversal |
| Vector search (top-10) | < 5 ms | Macrame DiskANN (measured: 264 µs) |
| Single-file update (file save → graph update) | < 500 ms (p95) | Macrame assertion + in-memory update |
| Startup graph projection (cold, 5K files) | < 5 s | Build from Macrame `links_current` |
| Integrity rebuild (10K files) | < 30 s | Full rebuild from ledger |
