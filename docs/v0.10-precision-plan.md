# v0.10 Improvement Plan — Precision

> **Date:** 2026-10-03 · **Baseline:** v0.9.4 (`51a895b`, `main`) · **Branch:** `dev_precision`
> **Source:** an external dogfood run of coderadar-rs 0.9.4 against
> [Lace](https://github.com/opticsWolf/Lace) (PySide6 docking library, 191 files,
> 2,674 functions, 21,148 call sites), during a real refactor that used
> `find_clones` / `get_smells` to drive and verify the work, followed by a
> sweep of the remaining API surface. Every root cause below was traced into
> the source on `51a895b`; every "Repro" is runnable.

---

## 0. Executive summary

v0.9 made the tool **robust**: nothing in this sweep crashed, fast paths are
fast (cold `analyze` 1.1 s, `update_file` ~40 ms, search 2 ms, query 1–10 ms),
and the clone/smell/mutation-planning layers did real work on a real refactor
(clone groups 61 → 41, with before/after LOC and cyclomatic deltas as the
acceptance check).

v0.10's theme is **precision**. The call graph — which dead-code, `callers`,
`affected`, rename and centrality all stand on — sees a minority of real
calls, and the places where it misses are mostly *silent*:

| Symptom on Lace | Truth (grep / AST) | Root cause |
|---|---|---|
| `callers_of(DockManager.add_dock_widget)` = **0** | 125 call sites | `var.m()` receivers never typed (§1.2) |
| `callers_of(DockManager.save_state)` = 1 | 29 call sites | same |
| `callees_of(DockManager.save_state)` = **[]**, `unresolved_targets` = **[]** | calls `self._serializer.serialize` | `a.b.m()` calls are **never extracted** (§1.1) |
| 1,996 / 2,674 functions "dead" (75 %) | 941 are pytest tests | smell rule ignores test roots (§2.1) |
| `eventFilter` **High, 0.90**, "removable_lines: 95" | Qt virtual override | size is scored as confidence; no external-override root (§2.2–2.3) |
| `constants: 0` | ~93 module constants in `lace/*.py` alone | module-level assignments dropped (§1.5) |
| `classes where inherits_from contains 'X'` → parse error | README example | keyword-prefix bug in the grammar (§3.1) |

Measured call-shape breakdown (Python `ast` over Lace, script in §8):

| Shape | Share | Status at v0.9.4 |
|---|---|---|
| `var.m()` | 41.6 % | extracted; resolved only if `var` is an imported **module** |
| `name()` | 37.5 % | extracted; resolved (functions), constructors of local classes → `external::` |
| `a.b.m()` (incl. `self._x.m()`) | 9.1 % | **not extracted** |
| `self.m()` | 6.3 % | extracted; resolved via MRO ✅ |
| `f().m()` | 5.0 % | **not extracted** |
| other | 0.7 % | not extracted |

So **~15 % of call sites never enter the graph**, and of the 42 % that are
`var.m()`, nearly all are dropped at resolution. Phase 1 targets both.

## Phase 1 — Call-graph recall (the main event)

### 1.1 Extract every attribute call, not just `identifier.method()`

**Root cause.** [`queries/python.scm:17–23`](../core_indexer/queries/python.scm)
has exactly two call patterns:

```scheme
(call function: (identifier) @call.name) @call
(call function: (attribute object: (identifier) @call.receiver
                           attribute: (identifier) @call.method)) @call
```

`Tag::Call` fires only on a match, so `self._serializer.serialize(v)`
(object is an `attribute`) and `Serializer().serialize(v)` (object is a
`call`) are **never handed to** `emit_call_for_node` — even though
[`walker.rs:647–715`](../core_indexer/src/extract/walker.rs) already handles
`attribute` nodes generically. Because nothing is extracted, nothing is
"unresolved" either, which is why `unresolved_targets` and
`traverse_unresolved` report a clean bill of health for a function with an
obvious outgoing call.

**Fix.**
1. Widen the pattern to `(call function: (attribute) @call.target) @call`
   (and the equivalent in the other grammars that have the same restriction —
   audit `javascript.scm`, `typescript.scm`, `ruby.scm`, `php.scm` for
   `object: (identifier)`-only receivers).
2. In `emit_call_for_node`, build `UnresolvedRef.path` as **segments**, not
   one text blob: `self._serializer.serialize` → `path = ["self", "_serializer"]`,
   `name = "serialize"`. For a call receiver (`f().m()`), record
   `path = ["<call:f>"]` so the resolver can type it from `f`'s return
   (§1.3) and so it is at least *counted* as unresolved.
3. Record the **name span** (byte offset of the method identifier) on
   `UnresolvedRef` — needed by §4.1 and cheap now.

**Acceptance.**
- Repro project (§8) `Manager.save_state` has a non-empty
  `unresolved_targets` *before* §1.2 lands, and a resolved edge to
  `Serializer.serialize` after.
- Lace: share of call sites present in `calls` (extracted) ≥ 99 %, measured
  by the §7 harness against the `ast` count.

### 1.2 Receiver typing for `var.m()` and `self.attr.m()`

**Root cause.** [`orchestrator.rs:280–345`](../core_indexer/src/resolve/orchestrator.rs)
classifies by `path.len()`:

- `path == ["self"|"cls"|"this"]` → `TypeInferenceRequired`, then an MRO
  lookup by bare name in [`resolve_calls.rs:75–85`](../core_indexer/src/graph/resolve_calls.rs) ✅
- lower-case single prefix → assumed to be a **module**; on miss →
  `NameNotInScope`. Every local variable, parameter and attribute receiver
  dies here.
- `path.len() >= 2` → `TypeInferenceRequired` with no follow-up.

Note the MRO fallback keys on **`raw.name` only** and runs for any
`TypeInferenceRequired`: once §1.1 makes `self._serializer.serialize` reach
it, it would wire the call to the *caller's own* `serialize` method if one
exists (the repro project has exactly this trap). Gate it on
`path == ["self"|"cls"]` **before** landing §1.1.

**Fix — a cheap, local, flow-insensitive type environment** (no full
inference; target the patterns that dominate real code):

| Evidence | Example | Binds |
|---|---|---|
| constructor assignment in the same function | `manager = Manager()` | `manager: Manager` |
| parameter annotation | `def f(manager: Manager)` | `manager: Manager` |
| `self.<attr> = <Ctor>(…)` anywhere in the class (typically `__init__`) | `self._serializer = Serializer()` | `Manager._serializer: Serializer` |
| annotated class/instance attribute | `_serializer: Serializer` | same |
| return annotation of a resolved callee | `def mgr() -> Manager` | `mgr().m()` → `Manager.m` |
| pytest fixture by parameter name | `def test_x(mgr)` + `@pytest.fixture def mgr() -> Manager` / `return Manager()` | `mgr: Manager` |

Implementation shape:
1. **Extraction:** `emit_field` currently returns early inside functions
   ([`single_pass.rs:312–315`](../core_indexer/src/extract/single_pass.rs)),
   so `self.x = Foo()` in `__init__` is dropped. Emit a new lightweight
   `ExtractedUnit::AttrBinding { class, attr, rhs_callee_path, annotation }`
   for `self.<id> = <call>` / annotated assignments, and
   `LocalBinding { function, name, rhs_callee_path | annotation }` for locals
   and parameters (parameters already carry annotations — reuse them).
2. **Resolution:** resolve the RHS callee with the existing machinery
   (sibling class → import → constructor). That yields a class id; then
   method lookup = the **same MRO walk** already used for `self.m()`.
3. Emit `ResolvedCall::Method { receiver: ReceiverShape::Typed(class_id), method }`
   with an **evidence tag** (`ctor-local`, `annotation`, `self-attr`,
   `fixture`, …) so dead-code can weight inferred edges (§2.4).
4. Keep it **one hop**: no inter-procedural propagation beyond "return
   annotation / single `return Ctor()`". Ambiguous bindings (two different
   constructors) → keep both edges, tag `ambiguous`.

**Acceptance.**
- Repro: `use_local`, `use_annotated`, `Manager.save_state` resolve.
- Lace: `callers_of(DockManager.add_dock_widget)` ≥ 100 (of 125),
  `callers_of(DockManager.save_state)` ≥ 20 (of 29). The remainder are
  `make_desk().manager.add_dock_widget` chains — tracked, not required.
- Precision guard: on the §7 corpus, no edge produced by this pass may point
  to a method of the *calling* class unless the receiver is `self`/`cls`.

### 1.3 Constructors of in-repo classes resolve to `external::`

Repro: `manager = Manager()` in the same file as `class Manager` →
`callees = ['external::Manager']`, and `Manager` is also listed as
unresolved. `resolve_one_function` only consults `sibling_funcs`
(functions), never sibling/imported **classes**
([`resolve_calls.rs:86–100`](../core_indexer/src/graph/resolve_calls.rs)).

**Fix:** add `sibling_classes` + imported classes to the `External(name)`
rewrite, producing `ResolvedCall::Constructor(class_id)` → edge to
`Class.__init__` (or the class node when no `__init__`). This is also the
missing *instantiation* signal RTA-lite needs (§2.5), and the type source for
§1.2.

### 1.4 `ClassName.method()` produces a dangling edge

Capitalised prefix → `ResolvedCall::Method { method: "Manager::add" }`
([`orchestrator.rs:303–308`](../core_indexer/src/resolve/orchestrator.rs)).
`"Manager::add"` is not an entity id; the repro shows
`callees_of(use_class_attr) = ['Manager::add', 'external::Manager']`.

**Fix:** resolve the prefix as a class name (sibling → import, same as §1.3),
then MRO-lookup `name`. If the class is unknown, return
`Unresolved { reason: NameNotInScope }` — never synthesise an id.
**Guard:** an invariant check (debug builds + one test) that every edge
target is either a real entity id or starts with `external::`.

### 1.5 Module-prefix resolution returns the *module*, not the function

Same function, lower-case branch: on a hit it returns
`matches[0].module_id` — i.e. the edge points at the module, not at
`module::name`. Repro: `serial.Serializer()` with `from pkg import serial` is
reported unresolved; when it does hit, the edge lands on the module node.
**Fix:** look `name` up inside the matched module (`find_symbol_in_module`,
already used a few lines below in `resolve_calls.rs`), fall back to the module
only for `import x; x()`-style module calls.

### 1.6 Constants are never extracted (`constants: 0` everywhere)

`ExtractedUnit::Constant` is consumed in `indexing.rs:218`,
`projection_ops.rs:629/940` and `storage.rs:882`, but **nothing in
`extract/` produces it**. The Python `(assignment left: (identifier))`
capture is routed to `emit_field`, which returns unless inside a class body.

**Fix:** in `emit_field`, when `current_class_idx` and
`current_function_idx` are both `None`, emit `ExtractedUnit::Constant`
(name, annotation, `default_value` = RHS source text, span). Restrict to
`UPPER_CASE` names *or* annotated names, to keep loop/temp module code out.
**Acceptance:** Lace `lace/*.py` reports ≥ 90 constants; `module_children`
lists them; queries can target `constants` once the entity is added to the
grammar (§3.4).

### 1.7 Function references (callbacks) are not edges

Qt `signal.connect(self._on_x)`, `QTimer.singleShot(0, self.f)`,
`map(fn, …)`, `sorted(key=fn)`, `atexit.register(fn)`, dict dispatch tables
`{"a": handler}` — all pass a function **as a value**. None of these produce
an edge, so every slot looks dead (§2).

**Fix:** extract *reference* sites: an `identifier` or `self.attr` /
`obj.attr` that resolves to a function and appears (a) as a call argument,
(b) as a dict/list element, (c) on the RHS of an assignment. Store as
`EdgeKind::References` (not `Calls` — keeps `callers` honest), and treat
`References` as reachability-propagating in dead-code.

## Phase 2 — Dead-code precision

### 2.1 The `dead-code` smell ignores test roots — and `find_dead_code` doesn't

Two code paths, two answers:

- [`smells/engine.rs:69–76`](../core_indexer/src/smells/engine.rs) computes
  reachability from `entries.production` only and hands it to
  [`rules/dead_code.rs`](../core_indexer/src/smells/rules/dead_code.rs),
  which flags *everything* not reachable — including every test function and
  fixture (941 of Lace's 1,996 findings).
- [`graph/deadcode/mod.rs:91`](../core_indexer/src/graph/deadcode/mod.rs)
  `detect_dead` correctly seeds `test_only` and skips `TestOnly` by default.

**Fix:** make the smell rule a thin adapter over `detect_dead` (one source of
truth): carry `kind`, `tier`, `score`, `removable_lines` into the finding's
`signals`, set `severity` from tier, and skip `test_only` roots exactly like
`find_dead_code`. Today the rule hard-codes `Severity::High` with
`reachable: 0.0` as its only signal.
**Acceptance:** `get_smells(rule_id="dead-code")` and
`find_dead_code(min_confidence=0)` return the same entity set on Lace and on
the repro project.

### 2.2 Size is scored as confidence

```rust
let size_boost = ((f.body_span.len() as f32 / 200.0).min(1.0)).max(0.3);
let score = combine(&[kind.isolation(), size_boost, quality]);   // mod.rs:123–129
```

`combine` is a product, so a 3-line dead function scores 0.27 (Speculative)
and a 95-line one 0.90 (**High**) with identical evidence. Size measures
*impact*, not *probability of being dead* — and large methods are exactly the
ones most likely to be framework overrides. This is how Lace's
`FramelessFloatingDockContainer.eventFilter` reached High/0.90.

**Fix:** drop `size_boost` from `score`; keep `removable_lines` as the
secondary sort key (already is). If a single "priority" number is wanted,
expose it separately (`priority = score × log(lines)`), never as `score`.
Re-baseline `tier_of` expectations in `findings_are_ranked_by_confidence_then_size`.

### 2.3 Overrides of external bases are entry points

Lace's 80 `*Event` / `eventFilter` / `paintEvent` / `sizeHint` methods are
called by Qt through virtual dispatch from a base class **outside** the
indexed root. The MRO already knows this: `Class.mro` contains
`MroNode::External(..)` entries
([`graph/mro.rs`](../core_indexer/src/graph/mro.rs)).

**Fix:** new entry-point step in
[`entry_points.rs:130`](../core_indexer/src/graph/deadcode/entry_points.rs):
a method is a production root when its class's MRO contains an external base
**and** no in-repo class in the MRO defines the same name (i.e. it overrides
something we cannot see). Cheap, framework-agnostic: covers Qt, Django
`View.get`, `unittest.TestCase.setUp`, `ast.NodeVisitor.visit_*`,
`logging.Handler.emit`, `json.JSONEncoder.default`, etc.
Same rule for Python `typing.Protocol` / `abc.ABC` members — abstract
declarations are interface, not dead code (Lace: `dock_menu.py`'s `menu_*_target`
Protocol members).

### 2.4 Framework packs (table-driven, opt-in by detection)

Some liveness is name/decorator convention, not dispatch:

| Pack | Detect by | Roots |
|---|---|---|
| pytest | `conftest.py` or `import pytest` | `test_*` functions/methods anywhere under a test path (not only immediate `tests/` parent — see note), `@pytest.fixture` (already), `conftest.py` hooks `pytest_*` |
| Qt | `PySide*/PyQt*` import | `@Slot`-decorated methods; targets of `.connect(...)` (needs §1.7) |
| click/typer | already partially (`click_subcommand_decorators…` test) | — |
| entry points | `pyproject.toml [project.scripts]` / `[project.entry-points]` | the named callables |
| `__all__` | module `__all__` list | listed names are public API even if the module is imported |

Note on `is_test_path`: it checks the file name and only the immediate
parent, so helper modules in nested test trees (Lace:
`tests/visual/corner_harness.py`, `tests/baselines/theme_tokens.py`) are
production code to the analysis, and everything they reach is "live in
production". The comment explains why ancestors are not walked; the concern
there is ancestors *above* the analyzed root, so walk ancestors up to — not
past — the root.

Weight inferred edges: a function kept alive only by `ambiguous` or
`fixture`-evidence edges (§1.2) gets `score × 0.8`, never "live for sure".

### 2.5 RTA-lite needs constructor edges

`rta_lite::uninstantiated_overrides` flags overrides on classes "never
constructed anywhere". With §1.3 missing, in-repo constructions like
`Manager()` are `external::Manager`, so classes look never-instantiated.
Re-run the RTA precision report (`docs/rta-lite-precision-report.md`) after
§1.3 and lower `RtaDead` to Speculative-only if precision < 80 %.

### 2.6 Explain every finding

`find_dead_code` records carry `kind/tier/score` but not **why**. Add
`evidence: [..]` (e.g. `["no inbound edges", "class has external base: none",
"not in __all__"]`) and `nearest_root_distance` for `TransitivelyDead`. This
is what makes a 0.9 trustworthy — or makes a wrong 0.9 obviously wrong.

**Phase-2 acceptance (Lace):** dead-code findings ≤ 10 % of functions;
zero `*Event`/`eventFilter`/`test_*`/fixture/Protocol entries; `as_spec_kwargs`
(called via `lace/theme_kit/chassis.py:128`) not flagged.

## Phase 3 — Query language

### 3.1 Keyword-prefixed identifiers fail to parse

[`grammar.pest:11`](../core_indexer/src/query/grammar.pest):

```pest
identifier = @{ !keyword ~ (ASCII_ALPHA | "_") ~ (ASCII_ALPHANUMERIC | "_")* }
```

`!keyword` has no word boundary, so any identifier **starting with** a
keyword is rejected: `inherits_from`, `index`, `input_count`, `order_id`,
`notes`, `byte_size`, `limit_x`, `asc…`, `selected`, `nullable`,
`contains_x`, `matches_x`, `group_*`, `true_*`. That is why the README's own
`classes where inherits_from contains 'BaseModel'` fails (BUGS_QUIRKS #6,
still open).

**Fix:** `keyword = @{ ("where" | … ) ~ !(ASCII_ALPHANUMERIC | "_") }`.
**Test:** a table test that every documented field name parses as a path,
and every README / MCP-tool-description query example parses and executes.

### 3.2 Unknown fields silently evaluate to `null`

[`exec.rs:799`](../core_indexer/src/query/exec.rs):
`fields.get(&name).cloned().unwrap_or(QueryValue::Null)`.
`functions where bogus_field == 1` returns 0 rows — indistinguishable from
"no matches", and typos (`file_path` on functions, which doesn't exist) look
like empty results.

**Fix:** a static field schema per entity (`FUNCTION_FIELDS`, …) checked at
parse/compile time; unknown field → `ValueError("unknown field 'bogus_field'
for functions; available: name, line, …")`. The schema doubles as the
documentation source (§3.5).

### 3.3 Rows have no identity

`scan_functions` / `scan_classes` / `scan_modules` iterate
`for (_id, …)` and discard the id ([`exec.rs:257, 401, 451`](../core_indexer/src/query/exec.rs)).
Function rows carry `name, line, line_count, callers, …` but no `id` and no
`file_path`, so a hit cannot be located or fed into `callers_of` /
`plan_rename`. (Dogfood F8 fixed the *CLI formatter*; the API still lacks it.)

**Fix:** always include `id`, `file_path`, `kind`, `parent_id` (cheap; they
are the row's key) regardless of `select`.

### 3.4 Coverage gaps in the schema

- `classes` rows: `decorators, line, method_count, name` — add `bases`
  (resolved ids + raw), `inherits_from` (transitive, from MRO), `is_abstract`,
  `docstring`.
- functions: add `file_path`, `parent_class`, `kind` (method/free/static/…),
  `is_override`, `complexity` (the smell metrics are already computed).
- operators: `starts_with`, `ends_with` (users reach for them first; `matches`
  works but needs regex).
- entities: `methods` as an alias for `functions where kind == 'method'`;
  `constants` (after §1.6). `entity` currently rejects `entities` and `methods`.

### 3.5 Errors and docs

- Parse errors are raw Pest debug structs
  (`ParsingError { positives: [atom], negatives: [] }`). Map rule names to
  human text: "expected a comparison operator (==, !=, <, >, contains,
  matches, in) at column 22".
- Ship `docs/query-language.md` generated from the grammar + field schema,
  and put the field list in `CodeGraph.query.__doc__` and the MCP tool
  description. `query_graph` currently has no docstring at all.

## Phase 4 — Mutation follow-through

### 4.1 Rename leaves resolved attribute calls "unverified"

[`mutation/mod.rs:1121–1143`](../core_indexer/src/mutation/mod.rs): any call
with a non-empty `path` becomes an `UnverifiedSite`, **even when the resolver
already proved the target** (`self.save_state()` in
`DockManager.add_perspective` resolves to the renamed method, yet
`plan_rename` asks for manual review). The blocker is that `UnresolvedRef`
stores the call's start column, not the method name's.

**Fix:** with the name span from §1.1, emit a real edit for resolved
`self`/`cls` calls and for §1.2 `Typed` receivers with non-ambiguous
evidence; keep `UnverifiedSite` for ambiguous/untyped receivers and textual
hits.

### 4.2 Rename must see the override family

`save_state` exists on 5 unrelated Lace classes. For a method that
overrides or is overridden (`overridden_by` / `overrides_base` indexes exist),
`plan_rename` should either rename the whole family or refuse with a list.
Add a test that renaming a base method in a 2-level hierarchy either covers
the override or warns.

## Phase 5 — API ergonomics & identifiers

### 5.1 Platform-stable entity ids

Ids embed native separators: `.\lace\dock_manager.py::DockManager.save_state`
on Windows, `./lace/…` on POSIX. Lookups normalise separators (forward slash
and `./` work — good), but **outputs** don't, so ids saved in one OS
(snapshots, baselines, MCP transcripts, CI artefacts) don't match on another.

**Fix:** canonical id = forward slashes, no leading `./`
(`lace/dock_manager.py::DockManager.save_state`) everywhere ids are
*emitted*; keep accepting the legacy forms on input for one minor version.
Requires a ledger migration (re-key) — plan it with a `store-repair` step.

### 5.2 Accept dotted qualified names

`find("lace.dock_manager.DockManager.save_state")` → `None`. This is the
spelling every Python user and every traceback uses. Add a resolver:
longest module prefix via `find_module_by_dotted_name` (exists, alias-aware
since v1 §2.2), remainder as the qualified symbol. On miss, return
"did you mean" candidates from `search_entities` instead of a bare `None`.

### 5.3 Inconsistent paths in findings

`find_scaffolding` placeholder findings use root-relative paths; **secret**
findings use the raw walker path, e.g.
`\\?\D:\User\Documents\Python\Lace\Lace\lace\dock_widget_tab.py`
([`scaffold/mod.rs:148, 171, 185`](../core_indexer/src/scaffold/mod.rs)).
`graph_stats()["indexed_root"]` also leaks the `\\?\` verbatim prefix.
**Fix:** one `display_path(root, path)` helper (strip verbatim prefix,
relativise, forward slashes) used by every finding type.

### 5.4 Byte spans need line/column companions

Clone instances, mutation edits and entity records expose
`span_start/span_end` as **byte offsets**. Entities already add
`line/end_line`; clones do not. Add `start_line/end_line` (and for edits
`line/col`) wherever a span is emitted — consumers had to re-read the file
and count newlines (CRLF files make that error-prone).

### 5.5 Implicit global graph

All `_core` functions act on `GLOBAL_GRAPH`
([`lib.rs:93`](../core_indexer/src/lib.rs)); `CodeGraph` is a facade over
whichever project was analysed last. Two graphs cannot coexist in one
process, and a stale global answers silently for the wrong tree
(`indexed_root` exists precisely to detect this after the fact).

**Fix (staged):**
1. Short term: every `CodeGraph` method checks its own `root` against
   `INDEXED_ROOT` and raises `StaleHandle` on mismatch (the exception class
   already exists in `__init__.py`).
2. Medium term: a `GraphHandle` pyclass owning an `Arc<CodeGraph>`; module
   level `_core` functions become thin wrappers over a default handle, so
   existing callers keep working.

### 5.6 Strictness / kind enums

`get_smells(strictness=…)` gives a good error for unknown values
(`expected: strict | normal | loose`) — extend that to `kind=` in
`search_entities` and `edge_kinds=` in `traverse` (unknown values currently
yield empty results). (Carries dogfood Issue 5's enum half.)

## Phase 6 — Noise in secrets, clones and smells

### 6.1 Secret regex flags identifier-like values

[`secrets.rs:29`](../core_indexer/src/scaffold/secrets.rs) generic rule:
keyword + quoted value ≥ 12 chars. Lace hits: `token="close_btn_color"` × 6
(a theme-token name), in source, tests **and** markdown docs.

**Fix:** require the value to look like a secret: Shannon entropy ≥ 3.5
bits/char **or** mixed character classes (upper+lower+digit) **and** not
matching `^[a-z][a-z0-9]*(_[a-z0-9]+)+$` (snake_case identifiers) or a
dotted/kebab identifier. Keep the vendor-specific patterns unchanged.
Also: the redaction keeps the first 8 chars of the *whole match*, which for
the generic rule is the keyword (`token="c***`) — redact the *value* and
show the key name in `label`.

### 6.2 Nested functions reported as clones of their parent

`gallery._spin` and its inner `draw` were reported as a clone pair; a
parent's body contains the child's text. **Fix:** in
[`clones/mod.rs`](../core_indexer/src/clones/mod.rs) drop pairs whose spans
nest (same file, one span ⊂ the other).

### 6.3 Table-shaped code as type-2 clones

Distinct dict-literal tables (`dock_theme._build_*` before the refactor) and
thin wrappers over a public API matched as type-2 clones: after identifier
normalisation, `{"a": x, "b": y}` blocks look identical. **Fix:** a
`literal_density` signal (share of tokens that are literals / keys); above a
threshold, require type-1 (exact) similarity, or down-weight via
`clone_confidence`. Make it visible as `reason: "literal-table"` rather than
suppressing silently.

### 6.4 `long-parameter-list` on Qt/py constructors

Strict mode reports 501 `long-parameter-list` findings on Lace; many are
keyword-only configuration constructors (`*, a=…, b=…`). Count only
positional-or-keyword parameters by default; keyword-only with defaults are
the remedy for this smell, not an instance of it.

## Phase 7 — Precision benchmark & CI gate

Nothing above stays fixed without a number guarding it.

### 7.1 Corpus

| Corpus | Why |
|---|---|
| `tests/fixtures/precision/py_shapes/` (new, ~15 files) | one file per call shape / binding pattern in §1, each with an `# expect: callers=…` header |
| Lace @ a pinned commit (PySide6, pytest) | real-world Qt + pytest; 21k call sites |
| CodeRadar `py_agent/` itself | dogfood; facade/registry patterns (dogfood Issue 2) |

### 7.2 Ground truth

A Python harness (`tests/precision/harness.py`) using `ast` for *extraction*
truth (every `ast.Call`, by shape — the script in §8) and, where available,
`jedi` (`Script.goto`) for *resolution* truth on a sampled 500 call sites per
corpus. Report:

- **extraction recall** = extracted call refs / `ast` calls
- **resolution recall** = edges agreeing with jedi / jedi-resolvable sites
- **resolution precision** = edges agreeing with jedi / edges emitted
- **dead-code precision** = sample 50 High+Medium findings, hand-labelled once,
  stored as a golden file

### 7.3 Gate

CI fails if extraction recall < 99 %, resolution precision < 95 %, or
resolution recall drops > 2 pts from the stored baseline. Baselines are
committed JSON so improvements ratchet.

Expected trajectory on Lace (to be confirmed by the harness):

| Metric | v0.9.4 (est.) | After Phase 1 target |
|---|---|---|
| Extraction recall | ~85 % | ≥ 99 % |
| Resolution recall (in-repo targets) | < 30 % | ≥ 70 % |
| Dead-code findings / functions | 75 % | ≤ 10 % |

## 8. Reproduction

Minimal project (one call shape per function), run with coderadar 0.9.4:

```python
# pkg/serial.py
class Serializer:
    def serialize(self, v): return str(v)

# pkg/manager.py
from pkg.serial import Serializer
from pkg import serial
LIMIT = 3
class Manager:
    def __init__(self): self._serializer = Serializer()
    def save_state(self, v=0): return self._serializer.serialize(v)
    def serialize(self): return "own method — must NOT be the target above"
    def add(self, x): return self.save_state(x)
    def mousePressEvent(self, event): pass
def use_local():              manager = Manager(); return manager.add(1)
def use_annotated(manager: Manager): return manager.save_state()
def use_module_attr():        return serial.Serializer().serialize(1)
def use_class_attr():         return Manager.add(Manager(), 2)
```

|---|---|---|
| `Manager.save_state` | `[]` | `[]` ← call never extracted |
| `Manager.add` | `[Manager.save_state]` ✅ | `[]` |

Call-shape counter (extraction-truth seed for §7.2):

```python
import ast, collections, pathlib, sys
shapes = collections.Counter()
for p in pathlib.Path(sys.argv[1]).rglob("*.py"):
    try: tree = ast.parse(p.read_text(encoding="utf-8"))
    except (SyntaxError, UnicodeDecodeError): continue
    for n in ast.walk(tree):
        if not isinstance(n, ast.Call): continue
        f = n.func
        if isinstance(f, ast.Name): shapes["name()"] += 1
        elif isinstance(f, ast.Attribute):
            o = f.value
            shapes["self.m()" if isinstance(o, ast.Name) and o.id in ("self", "cls")
                   else "var.m()" if isinstance(o, ast.Name)
                   else "a.b.m()" if isinstance(o, ast.Attribute)
                   else "f().m()" if isinstance(o, ast.Call) else "other.m()"] += 1
        else: shapes["other"] += 1
print(shapes.most_common())
```
