### ⚠️ §10.2 — Macrame Annotation Gap

**Finding:** `grammar_kind` is NOT persisted to Macrame in `build_concept()`/`entity_meta()`.

At `storage.rs:230-245`, the `ExtractedUnit::Class` arm does not include `grammar_kind` in the metadata JSON. It exists on the in-memory `Class` and `ExtractedClass` structs, is propagated through `patch.rs` and `graph.rs`, and is exposed to Python — but it will be lost on any reconstruction from Macrame.

**Impact:** Low. The `grammar_kind` is a display/debug field, not structurally load-bearing. Macrame reconstructs go through `build_concept()` which would need the field added. The in-memory graph has it; only cold starts from Macrame ledger would lose it.

**Recommendation:** Add to `entity_meta()`:
```rust
meta[annotation::GRAMMAR_KIND] = json!(&c.grammar_kind);
```

## Gap Analysis (v0.4.1 Update — all resolved)

### GAP-1: `grammar_kind` not persisted to Macrame — ✅ FIXED (v0.4.0)

**Location:** `core_indexer/src/storage.rs:230-245`

Added `annotation::GRAMMAR_KIND` constant and `meta[annotation::GRAMMAR_KIND] = json!(&c.grammar_kind)` in `entity_meta()` for `ExtractedUnit::Class`.

### GAP-2: Parameter/return type annotations not extracted — ✅ FIXED (v0.4.1)

**Location:** `core_indexer/src/extract/walker.rs`

`extract_parameters()` now handles `typed_parameter`, `default_parameter`, `typed_default_parameter`, and `keyword_argument` nodes. `is_builtin_type()` filtering applied to both annotation and return type fields. 2 new tests.

### GAP-3: Elixir function query too broad — ✅ FIXED (v0.4.1)

**Location:** `core_indexer/queries/elixir.scm`

Rewrote `(call)` capture to `(call target: (identifier) @_def_target (do_block) @_body) @function.def` with `#match? @_def_target "^(def|defp)$"` predicate. Module capture similarly refined. Name extraction via `arguments → alias` and `arguments → call → target` walks. Test tightened to assert specific function names.

### GAP-4: `grammar_kind` in Macrame annotation constants — ✅ FIXED (v0.4.0)

**Location:** `core_indexer/src/storage.rs`

Added `pub const GRAMMAR_KIND: &str = "grammar_kind";` to annotation constants block alongside existing `KIND`, `LINE`, `DOCSTRING`.
