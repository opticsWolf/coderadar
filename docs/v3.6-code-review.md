### ⚠️ §10.2 — Macrame Annotation Gap

**Finding:** `grammar_kind` is NOT persisted to Macrame in `build_concept()`/`entity_meta()`.

At `storage.rs:230-245`, the `ExtractedUnit::Class` arm does not include `grammar_kind` in the metadata JSON. It exists on the in-memory `Class` and `ExtractedClass` structs, is propagated through `patch.rs` and `graph.rs`, and is exposed to Python — but it will be lost on any reconstruction from Macrame.

**Impact:** Low. The `grammar_kind` is a display/debug field, not structurally load-bearing. Macrame reconstructs go through `build_concept()` which would need the field added. The in-memory graph has it; only cold starts from Macrame ledger would lose it.

**Recommendation:** Add to `entity_meta()`:
```rust
meta[annotation::GRAMMAR_KIND] = json!(&c.grammar_kind);
```

## Gap Analysis

### GAP-1: `grammar_kind` not persisted to Macrame (Low)

**Location:** `core_indexer/src/storage.rs:230-245`

**Description:** The `build_concept()` / `entity_meta()` function for `ExtractedUnit::Class` does not include `grammar_kind` in the Macrame concept annotations. The field exists in-memory and propagates through `patch.rs:124` and `graph.rs:1279`, but cold reconstruction from Macrame ledger would lose it.

**Spec reference:** §10.2 claims `grammar_kind` is a stored annotation.

**Fix:**
```rust
ExtractedUnit::Class(c) => {
    let mut meta = base;
    // ... existing fields ...
    meta["grammar_kind"] = json!(&c.grammar_kind);  // ADD
    (&c.name, &c.name, meta)
}
```

### GAP-2: Parameter/return type annotations not extracted (Deferred)

**Location:** `core_indexer/src/extract/walker.rs:1003`

**Description:** `extract_parameters()` sets `annotation: None` for all parameters. Return type at line 598 is always `None`. `is_builtin_type()` exists and is wired for class bases but has no surface to filter in parameters/returns because the fields aren't extracted.

**Spec reference:** Open question F.6 — deferred to when annotation extraction is added.

**Verdict:** Not a spec violation. Correctly documented as deferred.

### GAP-3: Elixir function query too broad (Deferred)

**Location:** `core_indexer/queries/elixir.scm`

**Description:** The `(call)` capture matches all function calls in Elixir, not just top-level function definitions. Spec F.5 recommends `call . (do_block)` or `def`/`defp` patterns.

**Spec reference:** Open question F.5 — deferred refinement.

**Verdict:** Not a spec violation. Correctly documented as known limitation.

### GAP-4: `grammar_kind` in Macrame annotation constants (Low)

**Location:** `core_indexer/src/storage.rs`

**Description:** The annotation constant `GRAMMAR_KIND` is not defined in the annotation module alongside `KIND`, `LINE`, `DOCSTRING`, etc. If GAP-1 is fixed, this constant should be added first.

**Fix:** Add `pub const GRAMMAR_KIND: &str = "grammar_kind";` to the annotation constants block.
