# CodeRadar v0.12 Improvement Plan

> **Date:** 2026-10-04 · **Baseline:** v0.11.0 (`337a17d`, `main`)
> **Input:** defects found during the v0.11 surface unification, the residue
> of [`open-items.md`](open-items.md) re-checked against `337a17d`,
> [`CODERADAR_BUGS_QUIRKS.md`](CODERADAR_BUGS_QUIRKS.md), and
> [`vector-embedding-integration-review.md`](vector-embedding-integration-review.md).

v0.11 gave every operation one name on MCP, the CLI and the Python API, and
routed all three through `coderadar.ops`. That makes the remaining defects
easier to fix once: a fix in `ops` reaches all three surfaces. The theme for
v0.12 is **make what the surface promises true**. Several operations now have
a clean name but answer wrongly (`as_of`), unstably (`find_clones`) or only
half the time (framework edges).

Each item lists the file to start in, what is wrong, the shape of the fix,
and how to tell it is done. Priorities: **P0** wrong answers, **P1** surface
rework, **P2** agent enablement, **P3** performance and persistence, **P4**
hygiene.

---

## P0 — Wrong answers

### 0.1 `as_of` answers from the present, and finds nothing

[`__init__.py`](../py_agent/src/coderadar/__init__.py) `Snapshot` ·
[`ops.py`](../py_agent/src/coderadar/ops.py) `as_of`

- `Snapshot` has no `find`, so `ops.as_of` (via `getattr(snapshot, "find", None)`)
  reports **every** symbol as "not found", on all three surfaces.
- Every other `Snapshot` method (`query`, `callers`, `callees`, `traverse`)
  delegates to the **current** graph. The timestamp is stored and never used.
- The Rust side can already do part of this: `_core.traverse(..., as_of=ts)`
  routes to Macrame's bitemporal ledger, downstream only
  ([`lib.rs`](../core_indexer/src/lib.rs) temporal branch; upstream raises
  `NotImplementedError`, see open-items §2.2).

**Fix.** Give `Snapshot` a real temporal backend. Do entity lookup through
Macrame `reconstruct(ts)` and downstream traversal through `_core.traverse(as_of=)`.
Every method that has no temporal path (query, callers, upstream traverse)
must raise `NotImplementedError` instead of answering from the present. Then
`ops.as_of` reports "not in the graph at T" and "temporal lookup unsupported"
as two different outcomes.

**Done when:** a test renames a function, then asks `as_of(before)` for the
old name and `as_of(after)` for the new name, and gets the right one each
time. Calling `Snapshot.query` raises. The API signature also needs to agree:
the MCP tool and CLI take `(timestamp, query, symbols)`, but
`CodeGraph.as_of(timestamp)` returns a `Snapshot`. Either add a
`CodeGraph.as_of(timestamp, query="", symbols=None)` lookup form or rename the
Snapshot factory (`snapshot_at`); the parity test then checks it.

### 0.2 Clone detection is nondeterministic

`core_indexer` clone engine · `ops.find_clones`

The same tree, run twice, returns different clone groups and a different
group order (found with the v0.11 determinism probe). Agents diff results
across runs, so a group that comes and goes reads as a regression.

**Fix.** Look for `HashMap`/`HashSet` iteration that feeds grouping or
truncation (`max_groups`). Sort candidates by `(file, start_line)` before
bucketing, and sort groups by `(size desc, first member id)` before the cut.

**Done when:** a test runs `find_clones` three times on a fixture and gets
byte-identical JSON each time.

### 0.3 Rust cross-module calls resolve to `external::`

Rust call resolution (`resolve_calls.rs`)

Calls to functions in a sibling module (`crate::graph::foo()`,
`super::bar()`, `use`-imported names) show up as `external::foo` on
CodeRadar's own Rust tree. This inflates dead-code findings on Rust
(`dead-code` currently ranks many `core_indexer` functions High) and hides
real call paths from `explore` and `affected`.

**Fix.** Map `crate::` / `super::` / `self::` paths and `use` aliases onto
module entities. This is the same job the Python import cascade does
(L2–L3).

**Done when:**
- a precision fixture with two Rust modules and cross-module calls resolves
  them all in-repo;
- the `self` corpus in `tests/precision` gains a Rust leg;
- the dead-code budget for `core_indexer` falls.

### 0.4 A fresh index retires hundreds of "stale" concepts

Seen on 0.11.0: `coderadar -C <CodeRadar> status` reported a fresh store,
re-analyzed anyway, and printed `retired 236 stale file concept(s) absent
from the fresh index` and `retired 46 stale edge(s)`. Either the store holds
ids for files the walk now excludes (expected, but then the store should not
have reported "fresh"), or two walks spell the same files differently.

**Fix.** First diagnose which of the two it is. Dump the retired ids. If they
are excluded paths, re-check freshness against the effective exclude set. If
they are spelling variants, the canonical-id work in 0.10 has a hole; add a
store test for it.

**Done when:** `status` followed by `reindex` on an unchanged tree retires 0
concepts.

### 0.5 Triage the bugs-and-quirks report

[`CODERADAR_BUGS_QUIRKS.md`](CODERADAR_BUGS_QUIRKS.md) lists ten issues from
2026-08-24, including #1 "`replace_body` corrupts indentation" (critical) and
#4 "docstring deleted on body replace". Several were probably fixed in
0.8–0.10, but the document has no status column.

**Fix.** Re-run each reproduction against 0.11 through the CLI. The edit
commands now give a dry-run diff for every case. Mark each issue fixed (with
the commit) or still open. Every one still open becomes a P0 item in this
plan.

## P1 — Finish the surface rework

### 1.1 Rendered text still speaks MCP on the CLI

[`render.py`](../py_agent/src/coderadar/render.py)

The CLI prints `render` text verbatim. That text still gives MCP advice:
- `explore_usage` explains the `symbols=` parameter;
- `NO_EMBEDDINGS` says to call `coderadar_compute_embeddings`;
- `search_miss` and `not_found` suggest `coderadar_search`;
- `edit` already takes an `apply_hint`, which is the one case done right.

**Fix.** Pass a small `Vocabulary` (tool name → how to invoke it on this
surface), defaulting to MCP. The CLI passes `coderadar <cmd>` spellings.
Extend `test_surface_drift` so the CLI's text never names a `coderadar_*`
tool.

### 1.2 The commands v0.11 did not convert

`cli.py`: `callers`, `callees`, `diagnose`, `visualize`, `shell`,
`exclude`, `git *`, `store-repair`

These still print through rich and have no `--format json`. `callers` and
`callees` go through `MacrameQuery`, not `ops`. Also, `err_console` is bound
to the real stderr at import time, so click's runner, and anything else that
swaps `sys.stderr`, cannot capture cold-start and config notes.

**Fix.**
- Add `ops.callers` and `ops.callees`, so the CLI and `CodeGraph` share them.
  Consider whether they are just `node --neighbors`; if so, keep them as
  CLI-only shortcuts that call `ops.node`.
- Give `diagnose` and `git` commands JSON output.
- Make `err_console` look up `sys.stderr` lazily (`Console(stderr=True)`).
- Rewrite `shell` on top of the op commands, or drop it.

### 1.3 Framework extraction: make it real or remove it

[`cli.py`](../py_agent/src/coderadar/cli.py) `_run_framework_extraction`

The function registers synthetic route→handler edges in the in-process graph.
The CLI exits straight afterwards, so the edges are lost; the MCP server never
runs it; and the README promises agents "can trace from URL patterns to
handler functions". In 0.11 it runs only in `init`, where it does nothing
except print counts.

**Fix (recommended).**
- Move extraction into `coldstart.build_graph` / `analyze`, so MCP and the
  CLI build the same graph.
- Persist the synthetic edges in the store, so a cold start keeps them.
- Add an `ops.reindex` stat for routes and handlers.

**Alternative:** remove it, and the README claim with it.

**Done when:** `coderadar_resolve "/users/:id"` → `affected` reaches the
handler in a fresh MCP session started from the store.

### 1.4 Delete the redundant star-export pass

`cli.py` `_extract_star_exports` re-does what `analyze()` already does for
`__all__`, and runs only in `init`. Delete it. Check that
`test_framework_resolvers` / star-export tests still pass against the
`analyze` path alone.

### 1.5 Tool-name prefix: decide once

Clients namespace tools as `<server>_<tool>`, so 0.11 shows
`coderadar_coderadar_explore`. There are two options:

| Option | Result in a client | Risk |
|---|---|---|
| Keep `coderadar_*`, recommend the server key `cr` in the docs | `cr_coderadar_explore` | none; docs only |
| Bare tool names (`explore`, `node`, …) | `coderadar_explore` | collisions under gateways that merge servers without prefixing; another breaking rename |

**Recommendation:** keep the names and change the docs. A third rename in two
releases costs more than the redundant prefix.

### 1.6 Deprecation schedule

v0.11 added warnings for these old names:
- `find`, `callers_of`, `callees_of`;
- `plan_body_replacement`, `plan_signature_update`;
- legacy `explore(start_id=…)`, `traverse(edge_types=…)`;
- the hidden CLI names.

**Fix.** State in the README that they are removed in **0.13**, and leave them
in place for 0.12. Remove the legacy `_walk` together with
`tests/test_explore_api.py::TestExplore` in 0.13.

### 1.7 Small API seams

- Re-export the error classes (`OpError`, `NotFound`, `InvalidRequest`, …)
  from the `coderadar` top level; the API raises them but users must import
  `coderadar.ops`.
- When `update_file` drops a deleted file, the report has made-up
  `epoch_before/after = 0`. Fill both in from the graph.
- The CLI never re-reads config after `reindex`. Fold in BUGS_QUIRKS #3:
  `ops.reindex` should re-activate `.coderadar.toml` on every surface.

### 1.8 `open_project`: switching projects from Python

`set_project` is the one operation with no Python form; the parity test
exempts it. Today a script switches by hand: `os.chdir`, then
`coderadar.load(<store>, ".")` or `coderadar.analyze(".")`. That skips the
config activation and the marker walk-up the other surfaces do.

**Fix.** Add `ops.open_project(path, confirm=False)`. It:
1. walks up from `path` to the nearest `.coderadar` marker, using
   `coderadar.markers.find_marker`; a directory without a marker is refused
   unless `confirm=True`;
2. `chdir`s to that root and activates its `.coderadar.toml`;
3. cold-starts from the store when it is fresh, and indexes otherwise
   (`coldstart.build_graph`);
4. returns `{"root", "marker", "source": "store" | "index", "stats"}`.

Expose it as `coderadar.open_project(path, confirm=False) -> CodeGraph`.
`coderadar_set_project` and the CLI's `-C` should use the same helper, so the
root rules live in one place.

**Done when:**
- the parity test maps `set_project` to `open_project` instead of exempting it;
- a test opens project A, then B, and gets B's ids and B's config;
- opening a subdirectory of B lands on B's root.

## P2 — Agent enablement (the deferred v0.11 step 5)

### 2.1 Two skills, checked against the code

- `skills/coderadar-mcp/SKILL.md` covers tool-first flows: explore → edit →
  update-file, plus the dry-run/apply discipline and the project_path rules.
- `skills/coderadar-cli/SKILL.md` covers the same flows as shell commands:
  `--format json`, exit codes and `-C`. Use it when no MCP server is running;
  it costs less context.
- Add a drift test: every `coderadar_*` / `coderadar <cmd>` named in a skill
  must exist (reuse the `test_surface_drift` regexes).
- Install both into `~/.pi/agent/skills`. Move the obsolete `codegraph-init`
  skill out; do not delete it. Update pi `directTools` to the 0.11 names.

### 2.2 Lace consumes 0.11

Build the 0.11 wheel and reinstall it into Lace's venv (`--reinstall-package
coderadar-rs`). Run Lace's CodeRadar-dependent checks against the renamed
tools.

## P3 — Performance and persistence

### 3.1 Embeddings: Phase 1 of the vector review

[`vector-embedding-integration-review.md`](vector-embedding-integration-review.md)

Do Phase 1 only:
- put the model id and preprocessing version in the dedup key;
- add dimension checks with explicit errors;
- decide which text gets embedded;
- remove the silent 10,000-per-kind cap in `ops.compute_embeddings`
  (`search_entities("", 10_000, kind)`). Large repos currently embed only part
  of the code, and nothing reports it.

Phase 2, persisting vectors through Macrame's vector API, waits for 0.13 and
starts only after Phase 1 has settled the contract.

### 3.2 Read commands never trigger a full analyze unasked

`_ensure_graph` falls back to a full `analyze` whenever the store is not
fresh. A read command such as `status` or `node` can therefore take tens of
seconds on a big repo.

**Fix.** Load the store even when it is stale. Then either re-parse just the
changed files (`coldstart.build_graph` already can), or answer with a staleness
banner, as MCP does with "changed on disk". Keep the full walk for `reindex
--full`.

### 3.3 `as_of` upstream traversal

This is open-items §2.2. It depends on Macrame's `TraversalBuilder` gaining
in-edges, or on CodeRadar storing reverse edges in the ledger. Schedule it
after 0.1 has made `Snapshot` honest.

## Out of scope for v0.12

- Embedding persistence in Macrame (vector review Phases 2–3) is planned for 0.13.
- Removing deprecated names (1.6) happens in 0.13.
- `IMPLEMENTS` as a separate edge kind, full tsconfig/pyproject path maps,
  arg-span indexing for `update_signature`, and Stack Graphs stay deferred
  (open-items §2.3–2.7).

## Release gate

- The parity, drift and determinism tests pass.
- `coderadar_as_of` / `coderadar as-of` / `CodeGraph.as_of` give the right
  symbol for a past and a present timestamp.
- Every BUGS_QUIRKS entry is marked fixed or carried with a reason.
- Clippy is clean and the CI lint leg blocks merges.
- The CHANGELOG has a 0.12.0 entry.
