## 1. Overview & Design Pillars

CodeRadar is a hybrid Python/Rust tool that maintains a **live, incrementally updatable semantic graph** of a source codebase, enabling LLMs and developer tools to both **query** and **safely rewrite** code through a unified pipeline.

### 1.1 Design Pillars

1. **Rust core, Python shell.** Tree-sitter parsing, diff engine, resolution cascade (L1–L3), mutation engine, and in-memory projected graph — all in Rust. Python provides the CLI, GraphRAG orchestration, embedding pipeline, LSP pool, MCP server, and framework resolvers. FFI uses flat buffers (one boundary crossing per file).

2. **Incremental by design.** After a file change, only affected symbols and their transitive dependents are recomputed. The diff algorithm matches entities by identity, not position.

3. **Name-based resolution with Stack Graphs.** Primary resolution uses the `stack-graphs` crate (12 languages). Falls back through import-constrained matching, signature matching, embedding similarity, and optional LSP — each with disjoint confidence bands.

4. **Partial coverage is worse than none.** The resolution cascade must close internal flows end-to-end or mark the entire chain unresolved. Internally-dead-end edges are suppressed. External edges (library calls) are always emitted with `target_kind: "external"`.

5. **Resilient to broken code.** Parse failures follow a deferred-to-recovery path rather than producing tainted symbols. Tainted updates are rejected (old graph slice retained). The graph never enters an inconsistent state.

6. **Read-write, not just read-only.** The MutationEngine provides AST-aware refactoring via four LLM tool calls: `replace_entity_body`, `update_signature`, `rename_symbol`, `create_entity`. All edits are byte-accurate, verified, atomic, and audited.

7. **Bitemporal persistence via Macrame.** All entities, edges, vectors, and audit data live in a single embedded `.db` file. The bitemporal model (valid time + transaction time) provides `as_of(ts)` and `reconstruct(ts)` for free — no custom WAL, no rollback journal, no epoch bumps.

8. **Hybrid query architecture.** Structural Pest queries execute against an in-memory projected graph (sub-ms). Agent traversals and temporal queries execute against Macrame (1.72 ms 3-hop). Vector search uses Macrame's built-in DiskANN.

9. **Framework-aware.** Django, Flask, and FastAPI route registrations are extracted as synthetic nodes and edges. These edges are registered in the Rust graph so agent tools (`callers_of`, `callees_of`, `explore`) can trace from URL patterns to handler functions.

10. **CodeGraph-informed.** v3.6 adopts proven techniques from the CodeGraph product (MIT-licensed, attributed in Appendix G): grammar-verified `.scm` queries, `grammar_kind` disambiguation, builtin type/noise filtering, function-as-value reference capture, docstring extraction, name stoplisting, and framework resolver patterns.

### 1.2 Language Tiers (v3.6)

| Tier | Languages | Resolution | Mutation |
|------|-----------|------------|----------|
| Tier 1 | Python, TypeScript, JavaScript, Rust, Go, Java, C, C++, Ruby, PHP, C#, Kotlin (12) | Stack Graphs → Import → Signature | Full tool suite |
| Tier 2 | Swift, Scala, Lua, Elixir, Zig, R (6) | Import → Signature | `replace_body`, `create_entity` |
| Tier 3 | Erlang, Haskell, OCaml, Nim, Dart, Julia, Perl, Shell, SQL, HTML, CSS, YAML, TOML, JSON, Markdown + 341 more | Signature Match only | `replace_body`, `create_entity` |

**Key v3.6 changes:**
- Kotlin promoted from Tier 2 to Tier 1 (full extraction via `class_declaration`/`object_declaration`/`function_declaration` with children walk)
- All 6 Tier 2 languages have grammar-verified `.scm` queries producing real function/class entities (no fallback `(comment)` queries)
- 18 languages indexed with 16 `.scm` files (TypeScript + JavaScript share one query file)

### 1.3 Non-Goals

- Type inference, type checking, or abstract interpretation
- Runtime behavior analysis (no execution)
- IDE / LSP integration as a primary feature (LSP is an optional fallback only)
- Semantic equivalence checking of refactored code
- Build-system parsing (we consume config, not build logic)
- Cross-language type bridges
- Security analysis / SAST
- Code metrics beyond structural counts

### 2.1 Layering Rules

1. The Python layer never holds Rust references across `await` boundaries or GIL releases.
2. Every `#[pyfunction]` and `#[pymethod]` releases the GIL during long Rust operations (`py.allow_threads`).
3. FFI uses flat buffers (Appendix A) — one boundary crossing per file. The Python decoder validates ABI version before unpacking.
4. Structural Pest queries execute against the in-memory projected graph. Agent traversals and temporal queries execute against Macrame.
5. Mutations stage in Rust, write to Macrame, then update the projected graph — all within the writer lock.
6. **v3.6:** Framework resolvers produce synthetic edges in Python; these are registered in the Rust graph via `register_synthetic_edge()` so agent tools can trace them.

## 3. Data Models

### 3.0 Identity Model

Entities are identified by stable dotted-path IDs (e.g., `"src/auth.py::UserService.create"`). These are used as Macrame concept IDs. Qualified names are *labels* — used for diff matching and display, not identity.

Framework-synthesized nodes use namespaced IDs: `"django:route:users/"`, `"fastapi:route:main.py:/items"`.

Diff matching uses a tiered key — see §5.2.

### 3.4 In-Memory Projected Graph

The projected graph is a **rebuildable derivative** of Macrame's ledger. It provides O(1) reverse-index lookups for structural Pest queries and L1/L2 resolution. It is NOT the source of truth — Macrame is. On startup, it is built from Macrame's `links_current`. On integrity violation, it is rebuilt from scratch.

| Scala | `scala.scm` | `class_definition`, `object_definition`, `function_definition` |
| Lua | `lua.scm` | `function_declaration`, `function_call`, `local_variable_declaration` |
| Elixir | `elixir.scm` | `defmodule`, `call` |
| Zig | `zig.scm` | `FnProto`, `VarDecl`, `FnCallArguments`, `BUILTINIDENTIFIER` |
| R | `r.scm` | `function_definition`, `call`, `comment` |

**v3.6 grammar verification:** Swift/Zig/R queries rewritten using grammar-verified node kinds (previously used fallback `(comment)` queries). Swift's `class_declaration` is disambiguated via `classify_class_like()` keyword scanning into `/struct`, `/enum`, `/interface` suffixes stored in `grammar_kind`.

### 4.4 Tagging + Walker (Two-Pass Extraction)

**Pass 1 — Tagging.** Tree-sitter `.scm` queries tag nodes with coarse classifications. `.scm` captures map to `Tag` variants. Query compilation is non-fatal — if a grammar's node names differ, a fallback chain `(comment) → (ERROR)` prevents crashes while still producing a module entity.

**Pass 2 — Hierarchy Walker.** A typed stack-frame walker traverses the tagged tree with frame kinds `Module`, `Class(EntityId)`, and `Function`.

### 4.5 Decorator Semantics

**Known-decorator table (Python):**

| Decorator | Effect |
|-----------|--------|
| `@staticmethod` | `FunctionKind::StaticMethod` |
| `@classmethod` | `FunctionKind::ClassMethod` |
| `@property` | `FunctionKind::Property` |
| `@<prop>.setter` | `FunctionKind::PropertySetter` |
| `@<prop>.deleter` | `FunctionKind::PropertyDeleter` |
| `@functools.cached_property` | `FunctionKind::CachedProperty` |
| `@abstractmethod` | `FunctionKind::AbstractMethod`; class becomes `EffectiveClass::Abstract` |
| `@dataclass` | `EffectiveClass::Dataclass`; synthesizes `__init__`, `__repr__`, `__eq__` |
| Unknown | Recorded in `decorators` field; no semantic effect |

### 4.6 Docstring Extraction (v3.6)

Two strategies, fallback-ordered:

1. **`preceding_docstring(node, source)`** — collects the comment run immediately before a declaration, climbing wrapper nodes (`export_statement`, `decorated_definition`, etc.). Strips comment markers (`#`, `//`, `/* */`, `/** */`, `--`, `--[[ ]]`, `(* *)`, `///`). Based on CodeGraph's `preceding_docstring` (MIT License).

2. **`@docstring` capture fallback** — if the preceding scan finds nothing, falls back to the tagged inline docstring from `.scm` queries.

Applied to both `Tag::Class` and `Tag::Function` handlers.

### 4.7 Function-as-Value Reference Capture (v3.6)

`scan_for_fn_ref()` scans five AST patterns for function references beyond direct calls:

| Pattern | Example |
|---------|---------|
| Assignment RHS | `self.on_click = self.handle_click` |
| Return values | `return handler` |
| Keyword arguments | `on=handler` |
| Argument lists | `register_callback(handler)` |
| Dict/list values | `{"key": handler}`, `[handler1, handler2]` |

Assignment RHS supports dotted access: `attribute`, `field_expression`, `member_expression`.

`resolve_fn_ref_candidates()` runs after the walk finishes — matches candidates against:
1. Same-file function names
2. **v3.6: Imported names** (`from .handlers import handle_click`)

Cross-file fn-ref resolution: a name from a `FromImport`/`RelativeImport` becomes a valid candidate, enabling `register` → `handle_click` edges even when `handle_click` is defined in a different file. Alias names are also tracked. Module-level imports (`import os`) are excluded.

Deduplication: no duplicate calls on the same function with the same (name, line, col).

### 4.8 Noise Filtering (v3.6)

**Builtin type filter.** `is_builtin_type(name)` covers 70+ builtins across all supported languages (Rust `i8`-`u128`, C `int`/`float`, Scala `Int`/`String`, Swift `Int`/`Double`, TS `string`/`boolean`, etc.). Applied to class `bases` extraction to prevent `class Foo(int)` from generating a bogus `int` reference.

**Literal receiver filter.** `is_literal_receiver(kind)` matches 20+ literal node kinds (`string`, `integer`, `true`, `STRINGLITERALSINGLE`, etc.). Applied to dotted call extraction to skip `"str".method()` and `5.times()` patterns.

**Name stoplist.** `is_stoplisted(name)` covers 12 names: `this`, `self`, `super`, `null`, `nil`, `true`, `false`, `undefined`, `NULL`, `nullptr`, `None`, `new`. Applied at:
- Walker level: all three call extraction paths (simple, dotted, Zig)
- Resolution level: `resolve_calls()` in orchestrator produces `UnresolvedReason::Stoplisted`

### 4.9 Parse Quality

- `Clean` — subtree has no errors
- `Partial` — subtree has errors but identifying fields intact
- `Tainted` — errors affect identifying fields; extraction is best-effort
- `Deferred` — file parse contains errors; routed to recovery extractor

### 4.10 Byte Span Extraction

Every entity and reference records byte spans from tree-sitter's native byte offsets:

| Entity | Spans |
|--------|-------|
| Function | `span`, `name_span`, `params_span`, `body_span`, `decorators_span` |
| Class | `span`, `name_span`, `body_span`, `decorators_span` |
| Constant | `span`, `name_span` |
| Import | `name_span` |

## 5. Incremental Update Algorithm

### 5.1 Update Flow

When a file changes:

1. **Parse** with tree-sitter → new `ExtractedUnit`s.
2. **Retrieve previous slice** from the projected graph.
3. **Diff** old vs new units → `Patch` of `Add | Remove | Modify`.
4. **Compute affected dependents** via reverse indexes.
5. **Write to Macrame** (assert/retire entities and edges).
6. **Update in-memory projected graph** (remove retired edges, insert new ones).
7. **Re-resolve only affected symbols.**
8. **Invalidate stale resolution cache entries.**
9. **Return `UpdateReport`.**

### 5.2 The Diff Algorithm

**Match key, in order of preference:**

1. `(kind, qualified_name, signature_hash, body_hash)` identical → no-op.
2. `(kind, qualified_name, signature_hash)` match, `body_hash` differs → `Modify { id, new_body_hash }`. No caller rebuild.
3. `(kind, qualified_name)` match, `signature_hash` differs → `Modify { id, full_fields }`. Affected callers re-resolve.
4. Unmatched old → `Remove { id }`.
5. Unmatched new → `Insert { unit }`.

}

## 6. Semantic Resolution Engine

### 6.1 Five-Layer Resolution Cascade

```
LAYER 1  Stack Graphs            confidence 0.90 – 1.00   (12 languages)
LAYER 2  Import Graph + Scope    confidence 0.80 – 0.89
LAYER 3  Signature Matching      confidence 0.40 – 0.79
LAYER 4  Embedding Fallback      confidence 0.20 – 0.39   (Python)
LAYER 5  LSP Override            confidence 1.00           (optional)
```

Bands are **disjoint by construction**: every resolver clamps its output into its band.

### 6.1a Partial Coverage Principle

A partially-resolved flow through **internal** entities is worse than an unresolved one. When the resolution cascade resolves some internal edges in a call chain but leaves gaps to other internal entities, the agent receives an incomplete graph.

**Rules:**
1. An edge to an **external** target is always emitted with `target_kind: "external"`.
2. An edge to an **internal** target whose own edges are missing MUST NOT be emitted. Mark the source's resolution as `Unresolved { reason: IncompleteFlow }` instead.
3. The `::toplevel` sentinel (§6.6) is always internal.

### 6.2 Layer 1 — Stack Graphs

Uses the `stack-graphs` crate (0.14+) with language-specific `.tsg` rule files for 12 Tier 1 languages.

### 6.3 Layer 2 — Import Graph + Scope

BFS over the import graph (up to `max_import_depth`, default 3), collecting modules that export the reference name. Confidence: single match → 0.89; multiple → 0.80.

### 6.4 Layer 3 — Signature Matching

Matches by name + arity, biased toward proximity. Weights: name=0.4, arity=0.3, proximity=0.3. Confidence: `(0.40 + score * 0.39).clamp(0.40, 0.79)`.

### 6.5 Layers 4–5 — Python-Side Fallback

- **Layer 4 — Embedding.** Cosine search in Macrame DiskANN. Threshold 0.85. Confidence 0.20–0.39.
- **Layer 5 — LSP.** If enabled, LSP `definition()` overrides with confidence 1.00.

### 6.6 `::toplevel` Sentinel

Every edge gets a valid source. References outside any function attach to the file's synthetic `{path}::toplevel` node.

### 6.7 v3.6 Stoplist Resolution

`resolve_calls()` in the orchestrator now checks `is_stoplisted()` on unresolved call targets. Matches produce `Unresolved { reason: Stoplisted }` — catching any stoplisted names that slipped past the walker-level filter.

Framework resolvers produce `SyntheticEdge` objects in Python. These are registered in the Rust graph via `register_synthetic_edge(source_id, target_id, kind)`:

1. Edges added to `ProjectedGraph.callees_by_caller` and `callers_by_caller` reverse indexes
2. Persisted to Macrame as `EdgeAssertion` with the edge kind (e.g., `HANDLES`, `REGISTERS`)
3. Immediately queryable via `callers_of()` / `callees_of()` / `explore()`

This is called automatically by the CLI during `analyze` and `init`.

### 28.4 AST Call Handling (v3.6)

All three resolver `_get_name()` methods now handle `ast.Call` nodes (traverse into `.func`), enabling extraction of handler names from expressions like `views.MyView.as_view()` and `Depends(get_db)`.

### F.4 `__all__` Static Analysis

Whether `__all__ += [...]` and `__all__.extend([...])` should be AST-pattern-special-cased. Left for real-world fixtures.

### F.5 Elixir Function Query Refinement (v3.6)

`defmodule` extraction works but function capture `(call)` is too broad. Refine to `call . (do_block)` or `def`/`defp` patterns.

### F.6 Parameter/Return Type Annotation Filtering (v3.6)

`is_builtin_type()` is wired for class bases but not parameter annotations or return types because the walker doesn't extract those fields yet. Wire when annotation extraction is added.
