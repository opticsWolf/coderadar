### 0.6 NEW — macrame-db 0.18 → 0.19 (blob prerequisite)

`core_indexer/Cargo.toml:28` · DR-3/DR-11 lineage

The blob API (`blob_put`/`blob_get`/`blob_stat`, sha256 content-addressed,
8 MiB default cap, hot→cold archive with read-through, no refcount) exists
only in 0.19. Upgrade unlocks §1.9/§3.0. Known coupling: `libsql` is pinned to
Macrame's own libsql (Cargo.toml:43-46 comment) — **bump both together or not
at all**. `tokio rt-multi-thread` is already a dependency, so the async
put/get bridge into the sync PyO3 path has runtime support (still needs a
`block_on` site — keep it in `storage.rs`, not in every caller). Verify the
migration creates `blobs` on 0.18 stores; note that pre-0.19 cold files read
blobs as *absent* (silent degradation — the upgrade test must cover a mixed
store, not just a fresh one).

**Done when:** `cargo tree` shows one libsql; a migrated 0.18 store reports a
`blobs` table; `blob_put`/`blob_get` round-trip from a Rust test; Python
surface untouched.

### 1.9 NEW — Blob write path: put-on-index

[`storage.rs`](../core_indexer/src/storage.rs) · DR-11

On every `analyze`/`update_file` file write-through:

1. `blob_put(file_bytes)` → digest. New bytes only — re-put refreshes
   `put_at` without rewriting (the common case is metadata-only).
2. Store the digest in the **file concept's `extra`** (e.g.
   `extra["source_blob"]`) inside that generation's assertion. This both
   versions the content bitemporally **and** keeps the blob hot-referenced
   (macrame-0.19 archive rule: a blob goes cold only when older than the
   cutoff *and* unnamed by any hot payload — concept `extra` qualifies).
3. Keep xxh3 `content_hash` for in-graph staleness; sha256 is only the blob
   address. **Digest hygiene is load-bearing:** lowercase hex, full 64 chars,
   inside payloads — an uppercased/truncated/stray digest silently orphans
   the blob at the next archive session. Assert the shape at the
   persistence boundary (one `validate_digest`-style check, tested).
4. Respect the caps: per-file 8 MiB blob cap vs 1 MiB watcher
   `max_file_size_bytes` — files the watcher skips never reach blobs;
   document that pairing so a raised cap in one place doesn't silently
  -doS the other.

Do **not** store diffs. Content addressing makes storage-diffs pointless
(unchanged files dedup to zero bytes); diffs are computed on read (§3.0).

**Done when:** reindexing an unchanged tree writes zero new blob bytes
(digest-stable); changing one file adds exactly one blob; the digest is
visible in the file concept's `extra` at that generation.

## P3 — Performance, persistence, retention

### 3.0 NEW — Blob read path: `as_of` serves old code

Completes §0.1. `Snapshot` resolves entity-at-T via `reconstruct(T)`, then
file-bytes-at-T via `blob_get(extra["source_blob"])`, then slices stored
spans. `read_source` gains a bytes-override (or a `read_source_at` helper);
everything else (render, MCP, CLI) stays unchanged — the bytes just come from
T instead of disk. Missing blob (pre-blob generations, pruned archives) is an
explicit outcome ("content unavailable for T", distinct from "not in graph at
T" and "unsupported"), never a silent present-tense answer.

**Done when:** the §0.1 test additionally asserts byte-equality of the old
function body; a pre-blob timestamp reports content-unavailable.

### 3.1 Embeddings Phase 1 (unchanged from v1)

Model id in dedup key, dimension checks, embed-what decision, remove the
silent 10k cap. Note: embeddings are future small blobs with a model id —
design Phase 1 keys so they become blob addresses later (0.13), no second
migration.

### 3.2 No unasked full analyzes (unchanged from v1)

Load stale stores; changed-files-only or staleness banner; full walk only for
`reindex --full`.

### 3.3 `as_of` upstream traversal — DECISION GATED

Was "schedule after §0.1". New information (blob design): upstream history
becomes *more* valuable once bodies are stored (callers-at-T with code), but
it still waits on Macrame in-edges or reverse-edge ledgering. **Do not invest
until §0.1 + §3.0 land and one real agent trace needs it.** Record the
go/no-go in the register (DR-9 row) instead of carrying it silently.

### 3.4 NEW — Retention + backup policy

Decide one archival cutoff (generations or days-hot) and document it; blobs
follow automatically via the reference scan. Store backup story must cover
**hot + cold files** (snapshots carry digests, never bytes — a hot-only
backup is a backup of pointers). Tie blob retention to ledger retention: one
cutoff, documented in `.coderadar.toml` or the store doc, enforced by the
same session.

**Done when:** the cutoff is written down; an archive session moves
unreferenced blobs cold and they remain `blob_get`-readable; backup docs name
both files.

## Diffs policy (applies to §1.9/§3.0/§3.1)

Compute, don't store. Structural change = two reconstructions compared;
textual change = fetch two blobs + diff on demand. No precomputed-diff rows,
no second invalidation problem. (If a hot path later needs cached diffs, key
them `(digest_a, digest_b)` — content-addressed like everything else.)
